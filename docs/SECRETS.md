# Secrets Management — Architecture Decision

**Status:** Decided 2026-06-03 (closes Kanboard Engineering #79)

## Problem

Secrets were managed as `scripts/secrets/*.env` files on the developer's machine —
a single point of failure with no redundancy, no audit trail, and no mechanism for
sharing across machines or team members.

## Decision: Two-tool split

Different secret categories have different threat models and access patterns. One
tool for everything is the wrong abstraction.

| Category | Tool | Rationale |
|----------|------|-----------|
| **Human secrets** — API keys, passwords, credentials you look up interactively | **Vaultwarden** (self-hosted, `vault.woodhead.tech`) | Bitwarden-compatible client ecosystem (browser ext, mobile, desktop). Lightweight: single Go binary + SQLite. No HA complexity. |
| **Machine secrets** — Ansible vars, Terraform creds, Docker env files consumed at deploy time | **SOPS + age** | Git-native, no server to maintain, works offline, no bootstrap problem, already used in the ShopStack credential rotator. |
| **SSH authentication** | **step-ca** (already at `192.168.86.36`) | Short-lived SSH certs. No change needed. |

## Ruled out

- **HashiCorp Vault** — HA Raft footprint too heavy for this homelab. Unseal/root-token
  bootstrap is non-trivial and creates its own chicken-and-egg problem.
- **Infisical** — adds a server dependency (Postgres, Redis) for marginal gain over SOPS.
  DX is good but the operational overhead isn't worth it at this scale.
- **Doppler / external SaaS** — introduces a third-party dependency and sends secrets
  off-prem. Self-hosted is the constraint.

## Migration path from scripts/secrets/*.env

1. Encrypt each `.env` file with SOPS + age: `sops --encrypt --age <pubkey> file.env > file.env.enc`
2. Commit the `.enc` files to git; add the plaintext files to `.gitignore`
3. Add a `make secrets-decrypt` Makefile target that writes plaintext to a gitignored
   `secrets/` dir at deploy time (requires the age private key on the operator's machine)
4. Store the age private key in Vaultwarden (the one truly off-machine credential)

This migration is tracked as a follow-up task — the immediate deliverable of this spike
is the architecture decision above and the Vaultwarden deploy (Kanboard #126).
